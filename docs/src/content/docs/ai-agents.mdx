An AI assistant that can run shell commands can use cv4pve-autosnap to tell you which snapshots the tool
has taken, and to take snapshots or apply a retention when you ask. Unlike cv4pve-report and cv4pve-diag,
`snap` and `clean` **change the cluster**: they create and delete snapshots.

## The cv4pve-autosnap skill

<AiSkill tool="cv4pve-autosnap">

- connect only with the options file, passed with `@`, and never print it;
- run `status` freely: it only reads;
- before any `snap` or `clean`, run the same command with
  [`--dry-run`](/cv4pve-autosnap/getting-started/#try-it-first), show you what it would create and remove,
  and run it only after you agree.

</AiSkill>

## Give it a token of its own

The skill tells the assistant what to do; the token decides what it can do. The assistant can read the
token and call the Proxmox VE API without cv4pve-autosnap, and the skill cannot prevent that.
`VM.Snapshot` also allows rolling a guest back to any of its snapshots: grant it, with `VM.Audit`, only on
the guests or the pool the assistant may snapshot, not on `/vms` — see
[Permissions](/cv4pve-autosnap/permissions/#privileges). For questions only, `VM.Audit` is enough. Put the
connection in an [options file](/cv4pve-autosnap/connection/#options-in-a-file), so the token stays out of
the conversation.
