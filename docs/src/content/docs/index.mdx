## Why

A snapshot is the quickest way back when something goes wrong inside a guest: a package upgrade that
breaks the boot, a bad configuration change, a script that deletes the wrong folder. Proxmox VE takes a
snapshot in one click, but only when someone remembers to click, and it never removes the old ones.
Snapshots that nobody removes pile up and fill the storage.

cv4pve-autosnap does both halves of the job: it takes the snapshot of every guest you select and removes
the oldest ones of the same label, so a schedule of *every two hours, keep 10* stays at ten snapshots per
guest, forever. Run it from cron or the Windows Task Scheduler at fixed times, or from your own scripts
right before an upgrade: no hand-written loop over the API to maintain.

## A snapshot is not a backup

:::caution[Keep your backups]
A snapshot lives **on the same storage as the disk** it belongs to. If that storage fails, is
corrupted or is deleted, the snapshots go with it. Use snapshots to go back a few hours after a
mistake; use [Proxmox VE backups](https://pve.proxmox.com/wiki/Backup_and_Restore) (vzdump, Proxmox
Backup Server) to survive the loss of a disk, a storage or a node. cv4pve-autosnap does not replace them.
:::

| | **Snapshot** (cv4pve-autosnap) | **Backup** (vzdump, Proxmox Backup Server) |
|---|---|---|
| **Where it is** | On the storage of the guest disks | On a separate storage |
| **Survives the loss of that storage** | No | Yes |
| **Going back** | Rollback in place, the guest returns to that moment | Restore, as the same or a new guest |
| **Cost** | Each snapshot keeps the blocks changed since it was taken: keep a few, for a short time | Space on the backup storage |
| **Needs** | A storage that supports snapshots: see the [storage table](https://pve.proxmox.com/wiki/Storage) | Any storage for the guest; a backup target |

## Where it fits

The cv4pve suite follows the Unix philosophy: each tool does one thing and does it well.
cv4pve-autosnap keeps recent restore points of the guests. Its companion in *continuous protection*,
[cv4pve-node-protect](https://github.com/Corsinvest/cv4pve-node-protect), saves the configuration of
the nodes, the part that guest backups do not cover.

Want the schedules, the history of the runs and HTTP webhooks from a web interface?
[cv4pve-admin](https://github.com/Corsinvest/cv4pve-admin) runs the same engine as its
[AutoSnap](https://corsinvest.github.io/cv4pve-admin/modules/autosnap/) module.

## Outside the nodes, API only

cv4pve-autosnap runs outside the cluster (on your workstation, a management VM or a scheduled job) and
talks only to the Proxmox VE REST API. Nothing is installed on the nodes and no SSH or root shell is
needed: an API token with the four privileges in [Permissions](/cv4pve-autosnap/permissions/) is enough.
Give it more than one node and it connects to the first one that answers, so the snapshots still run
while a node is down.
